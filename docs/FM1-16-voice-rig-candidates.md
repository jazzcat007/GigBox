# FM-1 16-voice rig: firmware candidates

> Research only, 2026-11-25. Nothing was flashed, backed up, restored or written to a unit, and no existing file was edited.

**Goal.** Four FM-1 units (A-D) on one DIN MIDI stream, through a thru box into each unit's TRS-A input. Each unit plays four parts: A = ch 1-4, B = ch 5-8, C = ch 9-12, D = ch 13-16. Each unit must filter its own block on the unit. Anything a unit sends leaves over USB only. Each unit should run a firmware from one family with a similar UI.

## Method and status key

- **Catalogue.** The cached copy is `~/fm1-hub/catalog.json` (catalogue `updated 2026-11-25 14:34 UTC`, sha256 `007c8639…008d22`). It was not re-fetched. Its `chip`, `version`, `sha256`, `lic` and `author` fields are the sources for Q5 and Q6 metadata.
- **Sources.** Each candidate's README, manual or release note was read at its catalogue tag with `gh api`. Line numbers (L…) refer to those files. Felucca 1.8.3 source (`firmware/src/*.c`) was read at tag `v1.8.3`. Where a README section is marked historical, the cell says so.
- **Status.** VERIFIED = a primary source states it as fact (source code or README/manual). UNVERIFIED = the source is silent, contradicts itself, or states it only for an emulator. NO = the source documents that the feature is absent or limited.
- **Packages.** No `.fwsc` package is in the local cache (`~/fm1-hub/` holds only `catalog.json` and `inspect.json`). The sha256 values are therefore the catalogue's declared values, not checked against a file (table a2).
- **Felucca 1.8.2.** Only 1.8.3 (the catalogue's version and the README's stable release) was read in source. The README links the 1.8.2 release notes for the flash-chip change.

## (b) Recommended four (one per unit)

| Unit | Channels | Firmware | Why it fits |
|---|---|---|---|
| **A** | 1–4 | **Felucca 1.8.3** | Native block CH1-4 on a new-chip firmware. Upstream of the family, 12 engines (FM6, PHYS, PHASE, WHEEL and others). |
| **B** | 5–8 | **Melodee 1.6.1** | Native block CH5-8 on a new-chip firmware. A modified Felucca with a different sound set: PROPHET, FM6, CZ-1, SID and DRUM. |
| **C** | 9–12 | **SLOOP 2.8.5** | New chip. Set the synth tracks to 9, 10, 11 and the drum track to 12 (GLO → MIDI). Drum kits and synth engines differ from A and B. |
| **D** | 13–16 | **sloopDX 4.0.1** | New chip. Set the synth tracks to 13, 14, 15 and the drum track to 16 (GLO → MIDI). Its single DX7 engine is the furthest sound from A-C. |

**Why this set.** These four use only firmwares marked `chip=new` and GPL-3.0. Two of them (A, B) have the block-of-four setting built in, so the unit needs one setting, not four. The other two (C, D) are SLOOP and its DX7 fork, which share the SLOOP UI, and take four per-track channel settings each. Every other candidate fails at least one requirement: GR!MM and ghoulbox are `chip=old`; fm1-dock and DX747 lack a verified TRS-clock or block path; JIANT's base-channel scheme spills into neighbouring blocks; OberVave has the right block but its Dinghy base is not in the Felucca family. OberVave is the fallback for C or D if SLOOP's four per-track settings prove awkward.

**Weakest assumption.** That the four units share one UI. The sources only support a family relation: Melodee is "a modified version of Felucca", SLOOP is built from Felucca 1.4/1.5, and sloopDX is "SLOOP's live workflow with a DX7 inside". The menu paths for the same action differ: Felucca uses MENU > MIDI > MIDI IN (seq.c L7), Melodee uses GLO > SYSTEM ROUT (README L582), and SLOOP and sloopDX use GLO → MIDI. No source compares the screens. So "same UI" is a family claim that has to be checked on the bench.

## (c) What only a real unit can settle

1. **TRS-A adapter and thru-box wiring.** GR!MM's manual says the wiring that the FM-1's jack needs "is still being tested" ([MANUAL L493](https://github.com/GRiMMBIENT/grimm/blob/v2.0.2/MANUAL.md)). SLOOP says "if nothing plays, try the other adapter type (A / B)" ([README L359](https://github.com/isod89/sloop-fm1/blob/v2.8.5/README.md)). Pick the adapter type that gives all 16 channels on each unit.
2. **Block isolation.** Send ch 1–16 from the thru box and confirm A answers only 1–4, B only 5–8, C only 9–12 and D only 13–16. For C and D the isolation depends on the four typed channels, so check every synth and drum channel, including the default drum channel 10 that SLOOP and sloopDX assume.
3. **Per-track settings survive power-off and firmware change.** The roadmap says data bytes survive a re-flash, but not that the setting is still read ([ROADMAP-device-settings.md §4](../docs/ROADMAP-device-settings.md)).
4. **Clock from TRS.** Each firmware claims TRS clock follow, but Melodee says its clock path has "not yet been tried with a real follower" ([README L62](https://github.com/keremimo/melodee/blob/v1.6.1/README.md)). Check start, continue and stop on all four.
5. **What leaves over USB.** Only USB carries clock or notes out. SLOOP has CLOCK OUT on USB ([README L73](https://github.com/isod89/sloop-fm1/blob/v2.8.5/README.md)); sloopDX has CLOCK OUT ([L70](https://github.com/zvenson/dxsloop/blob/v4.0.1/README.md)); Melodee sends clock on USB and Bluetooth ([L64](https://github.com/keremimo/melodee/blob/v1.6.1/README.md)). Confirm which unit is the USB clock master, and that a unit's clock does not leak into another's block.
6. **Save survives a power cycle on the new chip,** for each of A-D. The landscape doc's test ([docs/FM1-firmware-landscape.md §2](../docs/FM1-firmware-landscape.md)). Which chip each unit has is still unknown (landscape §7).
7. **Current A.** A runs grimm 2.0.2 ([ROADMAP-device-settings.md §3](../docs/ROADMAP-device-settings.md)), which the catalogue flags `chip=old`. If A is a new-chip unit, its saves will not persist until it is changed.
8. **Sound and load.** sloopDX's 14 DX7 voices are untested on this chip ([sloopdx README L339](https://github.com/zvenson/dxsloop/blob/v4.0.1/README.md)). Check dense chords on D.
9. **Melodee's DRUM redirect.** The DRUM channel is redirected "within the chosen range" ([README L585](https://github.com/keremimo/melodee/blob/v1.6.1/README.md)). Confirm it on B.
10. **Mutable Dreams, fm1-dock, DX747.** Their open items are the new-chip hardware test, block and per-part channels, and TRS clock. They are not in the recommended four, so they are left to a later pass.
11. **OberVave's accepted channel range.** Confirm that a base of 13 is accepted (L75 does not state the range), if OberVave is used for C or D.
